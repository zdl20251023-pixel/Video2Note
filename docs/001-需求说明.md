# Video2Note 德州扑克教学内容生产需求说明

- 日期：2026-11-24
- 状态：图文整理、稳定性及精简版需求已实施，完成自动检查和真实模型验证
- 适用项目：Video2Note
- 本次更新范围：两个模型精简产物及页签已实现，支持新链接自动生成、历史任务直接复用 Markdown，并已完成验证。

## 1. 背景与目标

当前项目已能跑通视频获取、内容处理和笔记生成流程。用户正在开发德州扑克教学 App，希望通过学习他人分享的视频，生成教学讲稿，并在后续使用其他工具根据讲稿制作动画。

项目需要从视频转笔记工具完善为教学内容生产工具：结合字幕、语音与画面理解视频，忠实还原牌局和讲解，生成可核对的视频信息整理及可用于动画制作的教学讲稿，同时保存有教学价值的关键图片。

核心完成标准：截图处理有完整记录、牌局信息可核对、关键画面可回看、讲稿能支撑后续动画制作。

完整产物保留证据与细节，新增“视频重点”和“精简讲稿”供快速阅读、复习与教学使用。精简需由外部大模型读取完整 Markdown 后完成，合并重复并重组重点，不以本地截断或简单删除段落替代。

## 2. 当前问题

1. 截图最短间隔为 15 秒，容易错过牌局动作和重要信息。
2. 产物目录仅按任务 ID 命名，无法直接判断对应视频。
3. 最多只向模型发送 8 张截图，不足以覆盖完整视频。
4. 现有总结偏向学习笔记，尚不能充分满足视频内容还原、教学改编和动画讲稿的需求。
5. 缺少关键截图筛选、去重、保存及 Web 展示能力。

## 3. 功能需求

### 3.1 提高截图密度

- 新增 3 秒、5 秒、10 秒截图间隔选项，保留较长间隔供用户选择。
- 前端选项、后端参数校验和实际截图处理逻辑应保持一致。
- 每张截图保留视频时间戳，以便关联字幕、语音、牌局动作及最终讲稿。
- 尽量覆盖位置、手牌、公共牌、筹码、底池、下注动作和教学文字的变化。
- 固定间隔采样不能保证捕捉所有瞬时变化；结合画面变化补充截图可作为后续增强，不作为本次已承诺的能力。

### 3.2 产物目录带上视频标题

任务产物目录采用“视频标题_任务ID”的形式，例如：

```text
artifacts/tasks/为什么只会抓诈远远不够？从谭轩的两手牌，看河牌加注诈唬的必要性_31619045-86b5-4636-90d3-29faf3632ef4/
```

- 视频标题用于人工识别，任务 ID 保证唯一性。
- 处理 Windows 文件名非法字符、路径长度、空标题及同名视频等情况。
- 标题获取失败时允许使用明确的备用名称，任务仍可继续处理。
- 网页查看、文件读取、下载、重试及重新总结都应能正确定位产物。
- 已有仅按任务 ID 命名的任务仍应正常访问，不强制迁移历史产物。

### 3.3 全量图片分析与分批汇总

- 启用图片分析后，取消最多发送 8 张截图的限制，全部采样截图必须进入图片分析流程。
- 不得静默截断、跳过图片，或将未完成的图片分析标记为全部完成。
- 根据所选模型的图片数量、上下文长度和接口限制，按视频时间顺序分批处理。
- 每批图片结合对应时段的字幕或语音转录分析；汇总时串联各批结果，保持牌局状态、行动顺序和教学逻辑的连续性。
- 最终总结综合全文文字证据和全部图片分析结果；不要求在单次请求中重新发送所有原始图片。
- 记录截图总数、已分析数、失败数及批次状态，并在 Web 界面展示处理进度。
- 失败批次应支持重试；存在失败或遗漏时明确告知用户，不得显示为完整分析成功。
- 所选模型或接口不支持图片输入时，明确提示并提供兼容模型选择，不能以仅处理文字替代图片分析完成。
- “全量分析”和“关键图片筛选”是两个独立步骤：最终展示去重后的关键图片，不代表可以提前丢弃未分析截图。

### 3.4 视频信息整理与教学讲稿

完整内容需要包含可独立查看、保存和导出的两类文档；两份对应的精简产物另见 3.7。

#### 3.4.1 视频信息整理

目标是忠实还原原视频，至少包含：

- 视频标题、主题、背景、适用场景和核心问题。
- 语音讲解的整理，以及画面对字幕和语音的补充信息。
- 牌局过程：位置、有效筹码、手牌、公共牌、底池、各街行动及下注尺度；原视频未提供的信息标记未知。
- 原作者的策略观点、推理过程、适用条件与结论。
- 关键时间戳、图片引用和证据关联，方便回看核对。

#### 3.4.2 画面文字化与牌局背景完整性

- 产品定位与主文档统一使用“视频信息整理”，先完整还原信息，再改编教学讲稿，不应过早压缩成学习要点。
- 模型必须理解画面，不以 OCR 或“关键决策”等泛化标题代替具体描述。尤其对牌局总览、策略图表、复盘页，应把图中的有效信息转成文字。
- 每张关键图片的文字描述至少包含：场景及牌局背景、可见人物与位置、手牌及公共牌点数/花色、筹码/底池/下注及单位、各街行动顺序、画面教学文字及策略解释、教学意义和待核对项。
- 牌局总览图需按翻前、翻牌、转牌、河牌逐街还原，不得只记录截图当时的最后一街；截图时间与画面回顾的牌局时间应区分。
- 只要画面提供了信息，即使语音没有重复讲解，也必须进入视频信息整理；模型不能只根据字幕写总结。语音和画面存在冲突时，分别记录来源并标记核对，不自行修正成唯一事实。
- 区分画面可见事实、原作者的策略评价和模型推断；没有展示的底池、筹码、牌面或行动不得补造。
- 教学讲稿应以融合后的完整文字材料为输入，包含来自图片的背景与逐街信息。

#### 3.4.3 教学讲稿

目标是服务德州扑克教学 App，并作为后续动画制作工具的输入，至少包含：

- 课题名称、学习目标、适用人群及必要的前置知识。
- 按教学顺序组织的讲解和可朗读的旁白。
- 分镜式描述：每段应展示的牌桌状态、人物行动、牌面变化、筹码变化和文字标注。
- 关键决策点、思考题、常见误区和课后总结。
- 每个教学片段关联的原视频时间戳及关键图片。

每个分镜应能表达以下信息；具体文件结构可在设计阶段确定：

| 字段 | 内容要求 |
| --- | --- |
| 片段编号与主题 | 标识教学顺序和本段要讲清楚的问题 |
| 来源时间与证据 | 原视频时间点或时段、关键图片引用 |
| 初始状态 | 本段开始时的位置、筹码、底池及已知牌面 |
| 画面与动作 | 需要展示的发牌、下注、弃牌、加注等动作及先后顺序 |
| 旁白 | 与画面和动作对应的教学讲解 |
| 教学标注 | 重点文字、数值、提示或思考题 |
| 待核对信息 | 来源不明确或无法可靠识别的内容 |

#### 3.4.4 内容准确性

- 明确区分原视频直接表达的内容、模型推断和教学改编。
- 看不清的牌面、花色、金额或听不清的讲解应标记待核对，不得编造后当作事实输出。
- 保持位置、牌面、金额、单位和行动顺序在全文及跨批次分析中的一致性。
- 字幕、语音和画面信息发生冲突时，应保留冲突说明供用户核对。
- 教学改编应保留适用条件，避免将特定牌局结论直接扩展为普遍策略。

### 3.5 关键图片筛选与展示

- 在图片分析流程中识别有教学价值的关键画面，合并重复或高度相似的截图。
- 关键画面包括牌局初始状态、公共牌变化、关键下注动作、策略图表、教学文字及总结页等。
- 去重不能误删细微但重要的变化，例如下注金额、行动方、牌面花色、筹码或底池变化。
- 同一画面存在多张候选截图时，优先保留清晰且信息完整的一张，并保留必要的时间关联。
- 每张关键图片附视频时间戳、简短内容说明和保留原因。
- 关键图片与视频信息整理、教学讲稿中的相关段落建立关联。
- Web 界面提供专门的关键图片查看区域，按视频时间顺序排列，支持放大查看。
- 关键图片保存在任务产物目录中，并包含在最终导出包内。
- 原始截图保留在 `images/`，关键图片额外复制到 `keyframes/`，去重不得删除原始证据或影响分析覆盖可核查性。

### 3.6 独立页签与真实产物状态

- 结果区域固定提供同级页签：**视频信息整理｜视频重点｜教学讲稿｜精简讲稿｜关键图片｜全部截图｜任务详情**。
- 教学讲稿参考视频信息整理的正文预览方式，点击后加载独立的讲稿文件；不得因元数据缺失而直接隐藏页签。
- 视频信息整理与教学讲稿正文不直接展开图片，包括历史学习笔记中的内嵌图片；保留时间戳及图片引用链接。只有点击“关键图片”或“全部截图”页签后才展示对应图片列表。
- 关键图片页显示详细画面描述、牌局信息、教学意义、时间戳和保留原因，并支持放大；不能只展示 OCR。
- 单文档下载跟随当前文档页签，ZIP 包包含独立文档、关键图片文件夹及索引。
- 根据实际文件状态提供页签内容和下载按钮。未生成、分析失败、部分内容或仅本地文字模式时明确说明原因及可执行的下一步，不无限加载或误报成功。
- 图片分析、信息整理和讲稿生成分别记录完成状态。个别分析或讲稿步骤失败，不应导致已完成的图文分析和关键图片全部消失。
- 对已有批次分析结果可在不重新调用模型的情况下恢复已有信息、关键图片与已有讲稿内容，但需显著标记覆盖范围和缺失内容；旧版描述不足时不得假称已完成新版视觉理解。

### 3.7 模型提炼的重点版与精简讲稿（已实施）

#### 3.7.1 两份独立产物

| 精简产物 | 主要输入 | 用途与内容要求 |
| --- | --- | --- |
| `视频重点.md` | 任务产物中的完整 `视频信息整理.md` | 快速理解视频主题、核心问题和结论，保留必要人物、位置、手牌与公共牌、关键行动及尺度、决策转折、推理依据和策略适用条件 |
| `精简讲稿.md` | 任务产物中的完整 `教学讲稿.md`，结合视频重点核对事实 | 保留可直接朗读的旁白及制作动画所需的关键分镜、初始状态、动作、标注和教学主线，不能缩成只有标题或几个要点的提纲 |

- 必须把实际读取的 Markdown 内容发送给外部大模型做提炼；不能只用数据库中的标题、概要或已有重点代替完整源文档。
- 完整文档保留，新增两份文件存放在同一任务产物目录，不覆盖完整版本。
- 视频重点不能机械替代精简讲稿的主输入：两者分别对应各自完整版本，精简讲稿还必须保留教学表达与动画动作。

#### 3.7.2 提炼质量与事实约束

- 合并重复描述、逐帧重复记录、反复出现的背景与前置知识、冗长说明及重复总结，按主题或牌局组织成连贯内容。
- 同一手牌多次出现时合并为连续的牌局过程；精简讲稿合并重复分镜和相邻重复讲解。
- 保留真正影响理解和决策的内容，包括人物位置、牌面花色、金额及单位、各街行动顺序、下注尺度、决策依据和策略前提。
- 不同牌局、不同街道、不同条件下的相似观点不能误合并；存在矛盾的信息不能当作重复内容直接删除。
- 关键待核对项集中列出，保留原作者观点、模型推断及教学改编的区别；未知内容不能在精简后变成确定事实。
- 按信息重要性减少冗余，不强制所有视频压成相同字数，不机械截断，也不能靠删去关键事实达成缩短。
- 保留少量有用的时间戳及图片引用链接，支持回溯；两份精简文档正文也不直接展开图片。
- 长文需完整进入处理。超过模型上下文限制时分段提炼，再全局合并、去重和重组，不能只发送开头或静默丢弃尾部。

#### 3.7.3 新视频链接流程

- 新链接须支持自动生成两份精简文档：先完成对应完整 Markdown，再进入模型提炼阶段。
- `视频信息整理.md` → 模型提炼 → `视频重点.md`。
- `教学讲稿.md` + 视频重点 → 模型提炼 → `精简讲稿.md`。
- 两项精简是可独立记录、保存和续跑的后处理步骤，显示各自的等待、处理中、成功、失败状态及原因。
- 精简失败不使已有完整产物失效，不阻断查看和下载；可单独重试，不能为此重跑视频获取、语音转录、OCR、图片分析或完整讲稿生成。
- 用户选择本地整理或未配置可调用模型时，明确提示精简版需要模型，不得把本地截断内容冒充模型提炼结果。

#### 3.7.4 已有任务直接生成

- Web 提供“生成重点版 / 重新提炼”入口，对已跑过的任务直接读取其现有产物文件并调用外部模型。
- 历史任务无需重新提交视频链接，也无需重新提取、识别截图或生成完整文档。
- 优先读取 `视频信息整理.md`；旧任务只有 `视频解析.md` 或 `学习笔记.md` 时，可兼容读取该现有文档，并保留其来源和覆盖范围说明。教学讲稿优先读取独立的 `教学讲稿.md`。
- 两份源文件都存在时，生成对应的两份新 Markdown；只有一份源文件时，明确说明另一份缺失的原因和所需下一步，不伪造缺失内容，也不因此隐藏已可生成的重点版。
- 源文件为部分内容或历史草稿时，精简版保留相同的完整性提示，不能冒充完整视频结论或完整讲稿。
- 精简结果保存到原任务对应的产物目录，并能在该任务的新增页签查看；不要求复制整套素材或重新建立视频处理任务。
- 记录源文档内容指纹、实际模型及提示词版本等生成依据。输入未变时复用已完成结果；完整文档变化后提示精简版已过期，支持重新提炼，避免新旧内容混用。
- 历史补生成的模型任务也应有独立进度、有限次重试和取消机制，不能永久占用后续队列。

#### 3.7.5 Web 展示及导出

- 新增“视频重点”“精简讲稿”两个同级页签，点击分别加载 `视频重点.md`、`精简讲稿.md`，使用与完整文档一致的 Markdown 预览方式。
- 根据实际文件和生成状态显示内容。尚未生成时提供明确生成入口，失败时显示具体原因和独立重试入口，不能无限加载或拿完整文档冒充精简文档。
- 支持两份新文件的独立下载，并加入完整 ZIP 文件包；下载入口跟随当前文档页签。
- 保留完整版本和关键图片页签，方便在精简版、完整内容与原始证据之间核对。

## 4. 预期使用流程

1. 用户提交视频链接，选择截图间隔、模型及相关处理选项。
2. 系统获取视频标题、字幕或语音转录，并按所选间隔采样截图。
3. 系统按视频顺序将全部截图与对应文字分批分析，展示进度和失败情况。
4. 系统汇总各批结果，还原完整牌局与教学逻辑，筛选并整理关键图片。
5. 系统先生成融合图文的视频信息整理，再以此为依据生成独立教学讲稿，关联时间戳及图片引用，标记待核对信息。
6. 新视频在完整文档生成后，调用模型生成视频重点和精简讲稿；精简阶段独立保存与重试。
7. 用户在 Web 界面查看完整版本、精简版本和关键图片，下载所需文档或完整产物包。
8. 对已跑过的历史任务，用户可直接从现有 Markdown 生成两份精简产物，不重跑前面的处理阶段。

## 5. 产物要求

产物文件与目录须实际生成，不能仅在界面声明存在：

- `视频信息整理.md`：融合语音、字幕及模型提取的画面信息。
- `教学讲稿.md`：独立讲稿，包含旁白与分镜描述，不能直接复制视频信息整理内容。
- `视频重点.md`：由模型基于完整视频信息整理进行去重、提炼和重点重组。
- `精简讲稿.md`：由模型基于完整教学讲稿提炼，保留可朗读旁白与关键动画分镜。
- 精简生成状态与来源记录：包括实际源文件、内容指纹、模型、版本、完整性与过期状态。
- 转录、字幕等原始文字证据。
- `images/`：原始采样截图；`keyframes/`：去重后的关键图片，须额外复制一份。
- 关键图片索引：按视频顺序记录说明、来源时间、保留原因、画面事实、牌局背景和段落关联。
- 全量截图分析记录，包括批次进度、失败情况和分析覆盖情况。
- 可下载的完整产物包。

Agent 新增的需求、设计、开发说明等项目文档统一存放于 `docs/`。视频任务运行时产物继续使用应用既定的 `artifacts/tasks/` 目录。

## 6. 验收标准

| 编号 | 验收项 | 通过条件 |
| --- | --- | --- |
| AC-01 | 截图间隔 | 用户可选择 3、5、10 秒，后端接受并按所选间隔采样，图片具有时间戳 |
| AC-02 | 目录命名 | 新任务目录包含处理后的标题及任务 ID；非法字符、长标题和同名视频不导致失败 |
| AC-03 | 历史兼容 | 原有任务的查看、文件读取、重试、重新总结和下载仍正常工作 |
| AC-04 | 全量覆盖 | 对超过 8 张截图的视频，每张采样截图都有可核查的分析状态，无静默遗漏 |
| AC-05 | 分批连续性 | 多批分析能按时间汇总，关键牌局状态和行动顺序保持连续 |
| AC-06 | 进度与失败处理 | 页面显示总数、已分析数和失败数；失败批次可重试，未完整分析时明确提示 |
| AC-07 | 模型能力 | 不支持图片的模型有明确提示，不能被当作已完成图片分析 |
| AC-08 | 视频信息整理 | 输出背景、讲解、牌局过程、策略逻辑及对应时间戳和图片证据 |
| AC-09 | 教学讲稿 | 输出学习目标、教学旁白、分镜动作、关键决策点和总结，支持后续动画制作 |
| AC-10 | 不确定信息 | 无法可靠识别或互相冲突的信息明确标注，不凭空补全为事实 |
| AC-11 | 关键图片 | 重复画面被合理合并，重要牌面、金额和行动变化不被误删 |
| AC-12 | 查看与导出 | 页面可按视频顺序查看并放大关键图片，完整导出包包含文档、关键图片和关联信息 |
| AC-13 | 页签与正文隔离 | 七个固定页签可见；四个文档页不内嵌图片，切换文档页签显示对应独立文件，图片只在对应图片页展开 |
| AC-14 | 关键图片独立落盘 | 关键图片实际复制到任务的 keyframes/，images/ 保留，索引引用正确，ZIP 包含二者 |
| AC-15 | 画面信息不遗漏 | 牌局总览中的人物、位置、手牌/公共牌花色、各街行动与数额、画面策略文字转成描述，并进入视频信息整理及讲稿依据 |
| AC-16 | 失败及历史状态 | 缺少讲稿时显示原因与生成入口；部分失败时仍可查看已完成的图片与文字，恢复历史结果不伪造未分析内容 |
